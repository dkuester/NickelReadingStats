# Development

Building, testing and verifying NickelReadingStats. For how the mod works see
[ARCHITECTURE.md](ARCHITECTURE.md).

## Building

Prerequisites: Docker and the toolchain image `strayrose/nickeltc`
(`arm-kobo-linux-gnueabihf`, GCC 11.5, Qt 6.5.2). Clone with submodules, since
NickelHook is a submodule:

```sh
git clone --recurse-submodules https://codeberg.org/hortizept/nickel-reading-stats.git
cd nickel-reading-stats/hook
docker run --rm --volume="$PWD:$PWD" --workdir="$PWD" strayrose/nickeltc make
docker run --rm --volume="$PWD:$PWD" --workdir="$PWD" strayrose/nickeltc make kobo
```

`make kobo` produces `hook/Kobo.tgz` with `imageformats/libreadingstats.so`.
A correct build links against Qt 6 only: `llvm-nm -D libreadingstats.so`
shows `@Qt_6` symbol versions and no `@Qt_5`.

> [!NOTE]
> `make clean` deletes `Kobo.tgz`. If a build fails with
> `arm-kobo-linux-gnueabihf-pkg-config: Command not found`, the image tag on
> your machine points to a different (Qt 5) toolchain; use the Qt 6 image
> explicitly.

## Testing

Three levels, from cheap to thorough.

### 1. Host unit tests

`hook/tests/` builds four binaries against the host Qt (5 or 6):

| Test | Covers | Needs |
|---|---|---|
| `test_wordcount` | Tokenising, body/script/comment handling, entities, UTF-16, href resolution, OPF spine parsing (`wordcount_logic.h`) | QtCore |
| `test_epub_words` | The real `count_epub_words()` incl. `QZipReader` against `fixtures/sample.epub` (generated by `fixtures/make_sample_epub.py`): spine alignment, percent-encoded hrefs, size limit | QtGui private headers |
| `test_hook_async` | Background word counting with fake libnickel pointers: delivery, cache, closed or reused views, joined in-flight counts | QtGui private headers, NickelHook submodule |
| `test_hook_gates` | Scoped `isTolino()` (range logic, gate vs. callee, unresolved gate), analytics and Google Analytics drop (Tolino/Kobo/unknown), fail-closed Activity entry | QtGui private headers, NickelHook submodule |

```sh
make -C hook/tests check
```

### 2. Firmware symbol & ABI check

`tools/check-symbols.py` verifies the hook against a real
`libnickel.so.1.0.0`:

1. Every hook (`.sym`) and dlsym (`.name`) symbol exists.
2. Every dlsym return convention (sret/value vs. reference/pointer) matches
   the declaration. A mismatch here caused the early book-open crash:
   `Content::getMimeType()` returns `QByteArray&`, not `QByteArray`.
3. Forwarded hooks return void/value as declared (e.g. `endReadingSession`
   returns the session length as `int`).
4. Class layout and virtual calls: `ReadingView`'s first base is `QWidget` at
   offset 0, and the virtual call in `supportsReadingStats()` resolves to
   `hasOnlyImages()` (via typeinfo/vtable relocations).
5. The `isTolino()` gates each call `isTolino()` with `bl`/`blx` and none calls
   a function that tail-calls it (PLT mapped via `R_ARM_JUMP_SLOT`, bounds from
   `.dynsym`).
6. The hard-coded `ReadingView` → `Content` offset (`0x94` on 5.18) matches
   the instruction in `updateWordCounts()` that computes it.

```sh
llvm-nm -D --defined-only libnickel.so.1.0.0 > defsyms.txt
python3 tools/check-symbols.py \
    --source hook/src/readingstats.cc \
    --defsyms defsyms.txt \
    --firmware libnickel.so.1.0.0
```

It needs Capstone (`pip install capstone`). A bare name list as `defsyms.txt`
also works but only checks existence (reported as `PARTIAL`). The firmware
files are proprietary and deliberately not in the repository.

### 3. CI

`.forgejo/workflows/ci.yml` runs on every push:

| Job | What |
|---|---|
| `wordcount` | Host unit tests against Qt 5 |
| `wordcount-qt6` | Host unit tests against Qt 6 |
| `symbols` | `tools/check-manifest.py` (source symbols match the firmware-verified `tools/symbols.txt`) and a syntax check of the tools |

`main` is protected: changes go through pull requests, and all three jobs
must pass before merging. The ARM cross-compile stays local (the toolchain
image is ~3.5 GB, too heavy for Codeberg's runners).

## Verifying on a device

`logread` shows that a hook ran; `.kobo/KoboReader.sqlite` shows that it
produced the right data:

| What | Where |
|---|---|
| Reading sessions | `Event` table, `EventType` 1020 (start) / 1021 (end) |
| Page turns | `Event` table, `EventType` 46 (written at the next session start) |
| Analytics queue | `AnalyticsEvents` table (should stay empty on a Tolino) |
| Google Analytics queue | `.kobo/Kobo/Analytics.conf`, key `Queue` (should stay empty on a Tolino) |

Open the database read-only (`sqlite3 "file:KoboReader.sqlite?immutable=1"`).
